# 2부 진행 플랜 — 대시보드로 45분 (2:15–3:00)

캔버스 v5 + 관리자 대시보드 기준. 프로젝터에는 대시보드(프로젝터 모드), Ji 노트북 둘째 화면에는 같은 대시보드의 관리자 모드. 학생은 QR로 canvas.html.
말은 합쇼체. 괄호 안은 대시보드에서 보는 곳.

## 준비 (2:05 휴식 중)

- 워커 주소가 들어간 수업판 빌드(`--class`)를 Pages에 올려 둔 상태. 폰 2대로 제출 1건 미리 넣고 지워 둔다.
- 대시보드 열어 PIN 입력 → 상단 "실시간 워커" 초록 점 확인. 빨간 "연결 실패"면 §잘못될 때.
- 칠판에 QR 2개: 캔버스, 1부 시뮬(각자 모드). 프로젝터는 프로젝터 모드(별명 숨김).

## 판정 버튼 쓰는 법

spotlight 모달 위 네 버튼. 누르면 그 학생 폰 아래에 초록 띠로 바로 뜬다.

| 버튼 | 언제 |
| --- | --- |
| 개념과 측정이 맞다 | 말한 차원과 묶은 문항이 같을 때 |
| 개념과 측정이 어긋난다 | 「어긋남」 표시가 있는 학생. 고쳐서 다시 내면 표의 그 행이 바뀐다 |
| 인과 방향을 다시 보자 | 종속에서 나가는 화살표를 지운 흔적이 있거나 연구질문이 "영향" |
| 선행연구 공백 | 선행연구 15편 미만 칸을 고른 학생 |

교수님이 누르시면 수업의 판정, 사양하시면 Ji가 누르고 "제가 대신 눌렀습니다"라고 말한다.

## 잘못될 때

| 상황 | 대응 |
| --- | --- |
| 대시보드 "연결 실패" | PIN 다시 입력(새로고침). 그래도 안 되면 워커 다운. Ji 노트북에서 캔버스·대시보드를 같은 브라우저로 열어 손들기 모드: 학생이 말하면 Ji가 대신 끌어 넣고 제출. spotlight는 그 노트북 화면 |
| 학생 폰이 캔버스를 못 연다(2.9MB 로딩) | 수업판은 검수본만 들어가 작다. 그래도 안 되면 옆 사람과 한 폰 |
| 끌기가 안 되는 폰 | 문항 카드의 + 버튼 |
| 제출이 5명 미만(2:32) | 2:32 격자 설명을 2:36으로 미루고 "종속변수 하나만 묶어 내십시오" |
| 교수님 판정 사양 | Ji가 누른다. 버튼 설명에 시간 쓰지 않는다 |
| 와이파이 전체 끊김 | 캔버스는 로컬 저장으로 계속 돈다. 제출만 안 됨. 2:38 spotlight는 학생 폰을 받아 HDMI 없이 Ji가 읽어 준다 |
